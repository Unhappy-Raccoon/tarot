# DECISIONS — реестр решений

Решения ниже утверждены пользователем. Их изменение требует отдельного согласования.

## Продукт и UX

### D-001 — Формат продукта
**Статус:** утверждено. Telegram Bot + Telegram WebApp. WebApp — основной интерфейс; бот — точка входа, уведомления, команды и fallback-сценарии.

### D-002 — Позиционирование и язык
**Статус:** утверждено. Personal Cosmic Journal, премиальный астрологический журнал, русский язык, стартовое позиционирование 18+.

### D-003 — MVP и монетизация
**Статус:** утверждено. Freemium + Premium + разовые покупки. Точные цены и лимиты открыты. Три стартовых расклада: карта дня; прошлое—настоящее—будущее; любовь и отношения.

### D-004 — Визуальная система
**Статус:** утверждено. Основной цвет — глубокий ночной #0B0A14; космический фиолетовый #5847B8 и лавандовый #A392D8 — вторичные, фоновые акценты; молочный #F1DCCB — текст и светлые элементы; золото #D9B983 — тонкие акценты. Playfair Display для заголовков и Inter для интерфейса. Не копировать Co–Star и другие чужие бренды/ассеты.

### D-005 — Анимации
**Статус:** утверждено. CSS 3D flip для карт Таро и астрологических карточек; ориентир 600–700 мс, ось Y, мягкое золотое свечение. Учитывать `prefers-reduced-motion`; Telegram Bot fallback — статичная карточка/изображение и inline-кнопки.

## Техническая архитектура

### D-006 — Архитектурный стиль
**Статус:** утверждено. Модульный монолит в monorepo. Без микросервисов на старте.

### D-007 — Основной стек
**Статус:** утверждено. React + TypeScript + Vite для WebApp; Node.js + TypeScript + Fastify для API; grammY для Telegram Bot; PostgreSQL + Drizzle ORM; CSS 3D для анимаций.

### D-008 — Общий код
**Статус:** утверждено. Отдельный workspace `packages/shared` для общих типов и схем.

### D-009 — Авторизация Telegram
**Статус:** утверждено. Серверная валидация Telegram WebApp `initData`; использовать только проверенные данные. Не доверять `initDataUnsafe`. Bot token и AI keys не попадают во frontend.

### D-010 — Астрологические вычисления
**Статус:** утверждено как направление; реализация подлежит тестированию. Astronomy Engine (MIT) — базовая библиотека планетарных расчётов. Асцендент и астрологические дома вынести в отдельный проверяемый модуль. LLM не выполняет расчёты. Swiss Ephemeris не выбран для MVP из-за модели лицензирования (AGPL или коммерческая лицензия).

### D-011 — AI-слой
**Статус:** утверждено. Провайдер подключается через adapter. Контекст собирается отдельно; лимиты проверяются сервером до вызова модели; версии системных инструкций сохраняются; повторяющийся ежедневный контент кэшируется. Конкретный AI-провайдер не выбран.

### D-012 — Платежи
**Статус:** утверждено. Для цифровых товаров/услуг внутри Telegram использовать Telegram Stars. Предусмотреть идемпотентность, подтверждение успешного платежа, возврат и поддержку. Месячное автопродление и годовой доступ за разовый платёж — разные сценарии; требования Telegram проверить перед реализацией.

### D-013 — Размещение
**Статус:** утверждено как рекомендуемая стартовая схема. Статический WebApp — Cloudflare Pages; API, бот, PostgreSQL и фоновые задачи — EU VPS. Перед production повторно проверить стоимость, backup, восстановление и требования к персональным данным.

### D-014 — Runtime baseline
**Статус:** зафиксировано для старта каркаса 2026-11-02. Node.js 26.13.0 LTS. Версии npm-пакетов указаны в workspace manifests; перед установкой/деплоем проверить security advisories и совместимость.

## Решения этапа 4

### D-015 — Репозиторий и структура
**Статус:** утверждено. npm workspaces monorepo: `apps/web`, `apps/server`, `packages/shared`, `assets`, `docs`.

### D-016 — Исходное состояние GitHub
**Статус:** подтверждено аудитом. На ветке `main` был только стартовый `README.md`; функционального исходного кода бота или WebApp нет. Этап 4 выполняется в `setup/project-foundation`; `main` не изменяется.

# AI-астролог — технические условия

## Назначение

Гибридный астрологический собеседник: пользователь выбирает готовую тему или задаёт свободный вопрос. Ответы предназначены для символической саморефлексии и не позиционируются как научные прогнозы.

## Реализованные сценарии

- **Отношения:** собственные чувства, взаимность, коммуникация и границы. Ассистент не утверждает, что знает мысли третьих лиц.
- **Мой потенциал:** ресурсы, сильные стороны, навыки и реалистичные шаги.
- **Энергия недели:** намерения, приоритеты и ритуалы. Реальные транзиты пока не рассчитываются.
- **Натальная карта:** интерпретация только доступных рассчитанных положений.

Сценарии разрешаются server-side allowlist; клиент не может передать свои system instructions.

## API

- `GET /api/ai/status` — доступность провайдера, план, usage и темы.
- `POST /api/ai/chat` — сообщение, optional conversationId и scenarioId.
- `GET /api/ai/conversations` — последние диалоги пользователя.
- `GET /api/ai/conversations/:id` — история своего диалога.
- `DELETE /api/ai/conversations/:id` — удалить диалог и сообщения.

Все endpoints требуют Telegram-сессию. Владение диалогом проверяется по Telegram ID.

## AI-провайдер

Первый adapter реализован для OpenAI Responses API через server-side HTTP-запрос к `/v1/responses`. Ключ никогда не передаётся в WebApp.

Для активации на сервере нужны:

```env
AI_PROVIDER=openai
AI_API_KEY=<server-secret>
AI_MODEL=<chosen-model>
AI_BASE_URL=https://api.openai.com/v1
```

Модель намеренно не закреплена в коде: её нужно выбрать по качеству русского языка, стоимости, доступности в выбранном аккаунте и требованиям к данным.

Запрос включает `store: false`. История всё равно сохраняется в PostgreSQL приложения, чтобы можно было продолжать и удалять диалоги. Условия обработки и удержания данных выбранным провайдером нужно проверить перед production.

## Контекст и минимизация данных

В запрос к модели могут попадать:
- текст текущего сообщения;
- ограниченная последняя часть переписки;
- краткий список рассчитанных знаков планет;
- знак Асцендента, только если он рассчитан.

Из профиля напрямую не отправляются дата рождения, время, город, широта и долгота. Если натальная карта отсутствует, ассистенту явно запрещено выдумывать положения.

Пользователь может самостоятельно вводить личную информацию в сообщениях; интерфейс предупреждает об обработке текста AI-провайдером.

## Лимиты и расходы

Текущие конфигурационные значения по умолчанию:
- Free: 5 сообщений на UTC-день.
- Premium: 50 сообщений на UTC-день.

Это временные значения, а не утверждённая тарифная политика. Лимиты меняются через `AI_FREE_DAILY_LIMIT` и `AI_PREMIUM_DAILY_LIMIT`.

Дополнительные ограничения:
- `AI_MAX_INPUT_CHARS=1200`
- `AI_MAX_HISTORY_MESSAGES=12`
- `AI_MAX_OUTPUT_TOKENS=500`
- `AI_REQUEST_TIMEOUT_MS=25000`

Дневная квота резервируется атомарно до обращения к провайдеру. При ошибке провайдера резерв освобождается. Фактические input/output tokens сохраняются для последующего анализа расходов.

## Хранение

- `ai_conversations` — диалоги пользователя.
- `ai_messages` — сообщения и метаданные провайдера/модели/токенов.
- `ai_daily_usage` — число сообщений и токены по пользователю и UTC-дате.

Удаление диалога каскадно удаляет сообщения. Общая политика срока хранения и полное удаление профиля отдельным API пока не реализованы.

## Ограничения

- Ответы не стримятся, UI ждёт готовый ответ.
- Реальный API-вызов не тестировался без серверного ключа и выбранной модели.
- Premium entitlement и Telegram Stars не связаны с user plan.
- Используется UTC-дневной лимит, не локальная полночь пользователя.
- Нет AI-интерпретации раскладов Таро и расчёта транзитов.
